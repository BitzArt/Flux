Flux - A Universal Web API client

Introduction

What is Flux?

Flux is an abstraction between your .NET application and external services. It provides a simple and consistent way to interact with those services without depending directly on how communication is implemented.

Flux is designed to be:

  • Easy to use — it provides common abstractions for interacting with external services.
  • Configurable — it is highly configurable and can be easily adapted to your needs.
  • Extendable — it supports implementation packages such as REST and JSON, and the core abstractions allow custom implementations.
  • Testable — it lets application code depend on Flux abstractions, so you can mock Flux components when testing your application.

Introduction

This guide shows how Flux.REST connects a .NET application to a Web API. It translates operations such as getting, adding, updating, and removing data into HTTP requests.

Installation

Install the Flux.REST NuGet package:

dotnet add package BitzArt.Flux.Rest

Get Started

Example API

The example uses Course and Student model classes. The school API identifies both models with integer values, and each Student can belong to multiple Courses:

public class Course
{
    public int? Id { get; set; }
    public string? Title { get; set; }
}

public class Student
{
    public int? Id { get; set; }
    public List<int>? CourseIds { get; set; }
    public string? Name { get; set; }
}

The school API supports the following operations:

Courses

OperationHTTP methodRequest URL
Get PageGEThttps://school-api.example.com/courses?offset={offset}&limit={limit}
GetGEThttps://school-api.example.com/courses/{id}
AddPOSThttps://school-api.example.com/courses
UpdatePUThttps://school-api.example.com/courses/{id}
RemoveDELETEhttps://school-api.example.com/courses/{id}

Students

OperationHTTP methodRequest URL
GetGEThttps://school-api.example.com/students/{id}
Get PageGEThttps://school-api.example.com/courses/{courseId}/students?offset={offset}&limit={limit}

Flux groups operations for a model and its identifier type into a Set. The Course Set uses the conventional courses collection-and-item pattern. The Student Set generally uses the students path, but Get Page is nested beneath a course and therefore needs its own endpoint configuration. The course identifier is supplied when that operation runs.

Configuration

Register Flux through your application’s IServiceCollection. A Flux Service groups the configuration for an external system. This example registers the school API as a Service and adds the Course and Student Sets:

services.AddFlux(flux =>
{
    flux.AddService("school-api")
        .UsingRest("https://school-api.example.com")
        .AddSet<Course, int>()
            .WithEndpoint("courses")
        .AddSet<Student, int>()
            .WithEndpoint("students")
            .WithEndpoint((GetPageOperationDescriptor _) => "courses/{courseId}/students");
});
  • AddFlux registers Flux with the application’s dependency-injection container and provides the builder used to configure Services.
  • AddService("school-api") registers the school API as a Flux Service.
  • UsingRest selects the REST implementation and configures the API’s base URL.
  • AddSet<Course, int> registers a Set for the Course model with int identifier.
    • WithEndpoint("courses") maps operations to the conventional courses endpoints.
  • AddSet<Student, int> registers a Set for the Student model.
    • WithEndpoint("students") maps operations to the conventional students endpoints.
    • WithEndpoint replaces endpoint configuration specifically for the Get Page operation.

GetPageOperationDescriptor identifies the operation being configured. When that operation runs, Flux replaces the {courseId} placeholder with an operation parameter and appends the pagination parameters to the query string.

Resolve Services and Sets

At runtime, IFluxContext provides access to the configured Services and Sets. It can be received through normal dependency injection; the following example resolves it directly from an IServiceProvider:

var fluxContext = serviceProvider.GetRequiredService<IFluxContext>();

var schoolServiceContext = fluxContext.Service("school-api");

var courseSetContext = schoolServiceContext.Set<Course, int>();
var studentSetContext = schoolServiceContext.Set<Student, int>();

Service("school-api") selects the configured school Service. Calling Set<TModel, TKey> returns the Set Context for the requested model and identifier types. These Set Contexts expose the operations used in the following examples.

Work with Courses

A Set Context exposes asynchronous methods for all supported operations. Use courseSetContext to execute the operations:

var coursesPage = await courseSetContext.GetPageAsync(offset: 0, limit: 20);

var course = await courseSetContext.GetAsync(courseId);

await courseSetContext.AddAsync(newCourse);
await courseSetContext.UpdateAsync(updatedCourse, courseId);
await courseSetContext.RemoveAsync(courseId);

Flux.REST translates these operations into the corresponding GET, POST, PUT, and DELETE HTTP requests shown in the Courses table.

Get Students for a Course

The students endpoint requires a course identifier. Pass courseId to the operation as a named parameter:

var parameters = new OperationParameterCollection(
    new List<KeyValuePair<string, object>>
    {
        new("courseId", 42)
    });

var studentsPage = await studentSetContext.GetPageAsync(
    offset: 0,
    limit: 20,
    parameters: parameters);

Flux replaces {courseId} with this named parameter and appends offset and limit. The resulting request URL is:

https://school-api.example.com/courses/42/students?offset=0&limit=20

Endpoint Configuration

In the Get Started section, the Course Set used one path for all its operations, while Student Get Page used a path configured for one operation. Endpoint configuration determines which path or request Flux.REST uses for each Set operation.

This page continues from those examples. It begins with common path configurations, then explains how operation parameters provide path and query values.

Configure Paths

A path configuration can apply at three levels:

  • all operations;
  • a specific HTTP method;
  • a specific operation.

Use this broad-to-specific order in configuration code: add a general WithEndpoint first, then add method-specific or operation-specific configurations. Each narrower configuration replaces the general one only for the operations it matches.

One Path for a Set

WithEndpoint configures one endpoint path for all supported operations in a Set:

.AddSet<Course, int>()
    .WithEndpoint("courses")

With the Service base URL from Get Started, calling courseSetContext.GetAsync(42) produces:

https://school-api.example.com/courses/42

Flux.REST creates the request URL by joining the non-empty parts in this order:

Service base URL / Set path / endpoint path / operation identifier

Here, UsingRest provides the Service base URL, WithEndpoint provides the endpoint path, and GetAsync(42) provides the operation identifier.

Alternatively, configure the same path when adding the Set:

.AddSet<Course, int>(path: "courses")

Paths by HTTP Method

Use a method-specific helper when operations that use different HTTP methods need different paths. Each helper applies its path to these built-in operations:

HelperOperations
WithGet("path")GetAsync, GetAllAsync, and GetPageAsync
WithPost("path")AddAsync without an identifier
WithPut("path")AddAsync with an identifier and non-partial UpdateAsync
WithPatch("path")Partial UpdateAsync
WithDelete("path")RemoveAsync

A Path for an Operation

The Student Set uses students for GetAsync, while GetPageAsync uses a path nested beneath a course. Both operations use GET, so WithGet("path") would configure both. To configure only GetPageAsync, use its operation descriptor type as the lambda parameter:

.WithEndpoint((GetPageOperationDescriptor _) => "courses/{courseId}/students")

For GetPageAsync, this configuration replaces the general students endpoint with the nested path.

The {courseId} is a path placeholder. The next section shows how to provide its value.

Operation Parameters

Operation parameters provide values for path placeholders and query parameters.

Named Parameters

Named parameters pair each value with a name. Flux.REST can use that name for a path placeholder or a query parameter:

var parameters = new OperationParameterCollection(
    new[]
    {
        new KeyValuePair<string, object>("courseId", 42),
        new KeyValuePair<string, object>("status", "active")
    });

var studentsPage = await studentSetContext.GetPageAsync(
    offset: 0,
    limit: 20,
    parameters: parameters);

For the path configured earlier, courseId replaces the {courseId} placeholder. The status parameter is not used by the path, so Flux.REST adds it to the query string. Get Page also adds its non-null offset and limit values:

https://school-api.example.com/courses/42/students?status=active&offset=0&limit=20

Parameter names must match placeholders exactly, including uppercase and lowercase letters. Named parameters must provide a value for every placeholder in the path.

Positional Parameters

You can also provide parameter values without names:

var parameters = new OperationParameterCollection(new object[] { 42, 7 });

Positional values replace placeholders from left to right, regardless of the placeholder names. For example:

courses/{courseId}/students/{studentId}

becomes:

courses/42/students/7

The number of positional values must exactly match the number of placeholders.

Control Automatic Query Parameters

By default, Flux.REST keeps any query string already present in the configured path, then adds unused named parameters and pagination values.

Set the path helper’s queryComplete argument to true when the configured query string is already complete.

For example, suppose the school API expects skip and take instead of offset and limit. Build those query parameters from the page request and mark the query as complete:

.WithEndpoint((GetPageOperationDescriptor operation) =>
{
    var skip = operation.PageRequest.Offset;
    var take = operation.PageRequest.Limit;
    return $"courses/{{courseId}}/students?skip={skip}&take={take}";
},
queryComplete: true)

Calling the Student Get Page operation now produces:

https://school-api.example.com/courses/42/students?skip=0&take=20

The resolver reads the requested pagination values and assigns the names expected by the API. Flux still replaces the courseId placeholder, but queryComplete: true prevents it from also appending the default offset and limit parameters.

HTTP Client Configuration

Flux.REST allows configuring an HttpClient for each Flux Service registered with UsingRest. The URL passed to UsingRest becomes the client’s BaseAddress.

Use ConfigureHttpClient to apply additional HttpClient settings for that Flux Service.

services.AddFlux(flux =>
{
    flux.AddService("example-api")
        .UsingRest("https://api.example.com")
        .ConfigureHttpClient((HttpClient client) =>
        {
            // Configure the HttpClient here
        });
});

The configuration applies to requests made through every Set belonging to the "example-api" Flux Service.

ConfigureHttpClient exposes the standard HttpClient configuration API. See the official HttpClient API reference for the available configuration options.

ConfigureHttpClient also has an overload that provides IServiceProvider when the configuration requires a registered dependency:

services.AddFlux(flux =>
{
    flux.AddService("example-api")
        .UsingRest("https://api.example.com")
        .ConfigureHttpClient((IServiceProvider serviceProvider, HttpClient client) =>
        {
            // Configure the HttpClient here
        });
});

JSON Serialization Configuration

Flux.REST uses System.Text.Json to serialize request bodies and deserialize response bodies.

Each Flux Service registered with UsingRest has its own JsonSerializerOptions. Use ConfigureJsonSerializer to configure those options:

services.AddFlux(flux =>
{
    flux.AddService("example-api")
        .UsingRest("https://api.example.com")
        .ConfigureJsonSerializer((JsonSerializerOptions options) =>
        {
            // Configure the JsonSerializerOptions here
        });
});

The configuration applies to JSON request and response bodies for every Set belonging to the "example-api" Flux Service.

See the official JsonSerializerOptions API reference for the available options.

Request Interception

Flux.REST provides two ways to inspect or modify outgoing requests and incoming responses: standard HttpClient message handlers and Flux.REST interceptors.

Message handlers participate in the HttpClient pipeline. Flux.REST interceptors run immediately before a request is sent and immediately after its response is received.

Both mechanisms are configured per Flux Service and apply to requests made through every Set belonging to that Service.

HTTP Message Handler

Create a custom HTTP message handler by deriving from DelegatingHandler and overriding SendAsync. A handler can inspect or modify a request before passing it to the next handler, then inspect the response after the downstream call completes.

See the official outgoing request middleware documentation for more information about the HttpClient handler pipeline.

public class CustomHttpHandler : DelegatingHandler
{
    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request,
        CancellationToken cancellationToken)
    {
        // Implement custom logic here
        return await base.SendAsync(request, cancellationToken);
    }
}

Register the handler in dependency injection with a transient lifetime, then pass its type to UsingRest<THandler>:

services.AddTransient<CustomHttpHandler>();

services.AddFlux(flux =>
{
    flux.AddService("example-api")
        .UsingRest<CustomHttpHandler>("https://api.example.com");
});

Flux.REST Interceptor

Create a custom Flux.REST interceptor by implementing IFluxRestInterceptor and providing the OnRequestAsync and OnResponseAsync callbacks. An interceptor can modify messages, add headers, or record request and response details.

public sealed class CustomInterceptor : IFluxRestInterceptor
{
    public Task OnRequestAsync(
        HttpClient client,
        HttpRequestMessage request,
        CancellationToken cancellationToken)
    {
        // Implement custom logic here
        return Task.CompletedTask;
    }

    public Task OnResponseAsync(
        HttpClient client,
        HttpResponseMessage response,
        CancellationToken cancellationToken)
    {
        // Implement custom logic here
        return Task.CompletedTask;
    }
}

Register the interceptor for a specific Flux Service with WithInterceptor<TInterceptor>.

WithInterceptor<TInterceptor> registers the interceptor type in the application’s dependency injection container, allowing it to receive registered dependencies through its constructor. The interceptor uses ServiceLifetime.Transient by default; pass another ServiceLifetime when a different lifetime is required.

services.AddFlux(flux =>
{
    flux.AddService("example-api")
        .UsingRest("https://api.example.com")
        .WithInterceptor<CustomInterceptor>();
});

Introduction

Flux.JSON initializes Flux Sets with data from JSON strings or files. It keeps the data in memory, making it useful for tests, prototypes, and other scenarios where an application does not need to connect to a remote service.

This guide assumes that you are already familiar with Flux Services, Sets, and Set Contexts from the Flux.REST introduction.

Installation

Install the Flux.JSON NuGet package:

dotnet add package BitzArt.Flux.Json

Get Started

The following example uses the school application introduced in the Flux.REST guide. Instead of requesting Courses and Students from the school API, the application loads them from JSON.

Example Data

The application uses the Course and Student models defined in the Flux.REST Example API. Define the initial Courses and Students as JSON arrays:

var coursesJson =
"""
[
  {
    "Id": 1,
    "Title": "Introduction to Biology"
  },
  {
    "Id": 2,
    "Title": "Advanced Mathematics"
  }
]
""";

var studentsJson =
"""
[
  {
    "Id": 1,
    "CourseIds": [1],
    "Name": "Alice"
  },
  {
    "Id": 2,
    "CourseIds": [1, 2],
    "Name": "Ben"
  },
  {
    "Id": 3,
    "CourseIds": [2],
    "Name": "Carla"
  }
]
""";

Configuration

Register a Flux Service and configure its Course and Student Sets:

services.AddFlux(flux =>
{
    flux.AddService("school-data")
        .UsingJson()
        .AddSet<Course>()
            .FromJson(coursesJson)
            .WithKey(course => course.Id)
        .AddSet<Student>()
            .FromJson(studentsJson)
            .WithKey(student => student.Id);
});
  • WithKey selects the identifier used by operations that address an individual model.

Resolve Services and Sets

Flux.JSON registers these Sets as IFluxSetContext<TModel>. Resolve the configured Service and its Sets through IFluxContext:

var fluxContext = serviceProvider.GetRequiredService<IFluxContext>();

var schoolServiceContext = fluxContext.Service("school-data");

var courseSetContext = schoolServiceContext.Set<Course>();
var studentSetContext = schoolServiceContext.Set<Student>();

Work with Courses

var coursesPage = await courseSetContext.GetPageAsync(
    offset: 0,
    limit: 20);

var course = await courseSetContext.GetAsync(courseId);

await courseSetContext.AddAsync(newCourse);
await courseSetContext.UpdateAsync(updatedCourse, courseId);
await courseSetContext.RemoveAsync(courseId);

These changes affect the in-memory Course data but do not change coursesJson.

Flux.JSON supports full updates; partial updates are not supported.

Get Students for a Course

When you need to filter JSON data using values supplied at runtime, configure EnrichQuery for the Set. It receives the current query and operation descriptor, allowing you to adapt the query before Flux produces the result.

In this example, the Student Set contains Students from every Course. EnrichQuery reads courseId from the Get Page operation and selects only Students enrolled in that Course:

.AddSet<Student>()
    .FromJson(studentsJson)
    .WithKey(student => student.Id)
    .EnrichQuery((query, operation) =>
    {
        if (operation is GetOperationDescriptor getOperation)
        {
            return query.Where(student => student.Id == (int?)getOperation.Id);
        }

        if (operation is GetPageOperationDescriptor &&
            operation.Parameters is INamedOperationParameterCollection parameters)
        {
            var courseId = (int)parameters.Values
                .Single(parameter => parameter.Key == "courseId")
                .Value;

            return query.Where(student => student.CourseIds!.Contains(courseId));
        }

        return query;
    });

For Get, the enriched query replaces the normal key lookup behavior. The GetOperationDescriptor branch therefore filters by the requested identifier.

Pass courseId when requesting the Student page:

var parameters = new OperationParameterCollection(
    new List<KeyValuePair<string, object>>
    {
        new("courseId", 1)
    });

var studentsPage = await studentSetContext.GetPageAsync(
    offset: 0,
    limit: 20,
    parameters: parameters);

The resulting page contains Alice and Ben, who are enrolled in Course 1.

EnrichQuery runs for Get, Get All, and Get Page. For Get Page, Flux applies pagination after enriching the query.

Load Data from Files

Use FromJsonFile when the initial data is stored in files. You can pass a base directory to UsingJson and a file name to each FromJsonFile call:

services.AddFlux(flux =>
{
    flux.AddService("school-data")
        .UsingJson("data")
        .AddSet<Course>()
            .FromJsonFile("courses.json")
            .WithKey(course => course.Id)
        .AddSet<Student>()
            .FromJsonFile("students.json")
            .WithKey(student => student.Id);
});

JSON Deserialization Configuration

Flux.JSON uses System.Text.Json to deserialize the initial data.

Each Flux Service registered with UsingJson has its own JsonSerializerOptions. Use ConfigureJsonSerializer to configure those options:

services.AddFlux(flux =>
{
    flux.AddService("example-data")
        .UsingJson()
        .ConfigureJsonSerializer((JsonSerializerOptions options) =>
        {
            // Configure the JsonSerializerOptions here
        });
});

The configuration applies to the initial data loaded for every Set belonging to the "example-data" Flux Service. Configure the options before calling FromJson or FromJsonFile.

See the official JsonSerializerOptions API reference for the available options.
