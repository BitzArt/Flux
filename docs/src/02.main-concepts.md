# Main concepts

This page introduces the main Flux concepts and how they fit together.

## Flux Service

A **Flux Service** represents one external system that your application communicates with.

Imagine your application works with a school API. In Flux, that API can be configured as a **Flux Service**. The service configuration defines how Flux communicates with that system, such as through a REST implementation.

## Set

A **Set** represents a configured model or resource within a **Flux Service**.

In a school API, the students resource can be configured as a **Set** for the `Student` model type.

A service can contain multiple sets. The same school API might expose sets for `Student`, `Teacher`, and `Course`.

## Set Context

A **Set Context** is the application-level abstraction used to execute operations on a **Set**.

In code, a **Set Context** is represented by `IFluxSetContext<TModel>` or `IFluxSetContext<TModel, TKey>`.

A **Set Context** for students gives your application a single place to fetch, create, update, or remove `Student` data without depending directly on how the school API handles those requests.

## Operations

An **Operation** is an action executed through a **Set Context**.

Flux provides common operations for working with configured sets:

- **Get All** — fetch all items.
- **Get Page** — fetch a page of items.
- **Get** — fetch one item.
- **Add** — create a new item.
- **Update** — update an existing item.
- **Remove** — remove an existing item.

The implementation package decides how each operation is translated. In the REST implementation, operations are translated into HTTP requests.
