# Introduction

## What is Flux?

Flux is a NuGet package for .NET applications that simplifies communication with external services. 

It acts as an abstraction between your application and those services, giving you a simple, consistent way to interact with them without tying your code to their implementation details.

## What problem does Flux solve?

Applications often need to communicate with external APIs or other data sources. Without a common abstraction, this code can become scattered, repeated, and tightly coupled to the details of each external system.

Flux helps you keep those details outside your application logic. Your code can focus on what it needs to do, while Flux and its implementation packages handle service-specific communication.

## Main Idea

Flux is designed around the [Dependency Inversion Principle](https://en.wikipedia.org/wiki/Dependency_inversion_principle): application logic should depend on stable abstractions, not on implementation communication details.

## What Flux is designed to be

- **Easy to use** — it provides common abstractions for interacting with external services.
- **Configurable** — it is highly configurable and can be easily adapted to your needs.
- **Extendable** — it supports implementation packages such as REST and JSON, and the core abstractions allow custom implementations.
- **Testable** — it lets application code depend on Flux abstractions, so you can mock Flux components when testing your application.
