# Endpoint Configuration

Endpoint configuration defines how Flux.REST turns Set operations into HTTP requests. When an operation runs, Flux.REST uses the endpoint configuration that matches it. If no configuration matches, Flux.REST builds the request from the configured Service and Set paths.

## Configure Paths

Flux.REST can configure a path for all supported Set operations, for an HTTP method, or for one operation.

### One Path for a Set

`WithEndpoint` configures an endpoint path for all supported operations in a Set:

```csharp
.AddSet<Course, int>()
    .WithEndpoint("courses")
```

Flux.REST builds the request URI by joining the non-empty parts in this order:

```text
Service base path / Set path / endpoint path / operation identifier
```

The Service base path comes from `UsingRest`, and the endpoint path comes from `WithEndpoint`. Flux.REST appends an identifier when the operation has one.

A path passed to `AddSet` is the Set path:

```csharp
.AddSet<Course, int>(path: "courses")
```

For a simple Set endpoint, use either the `AddSet` path or `WithEndpoint`; do not repeat the same path segment in both. Configure both only when they represent different parts of the path. When both are configured, the Set path comes first.

### Paths by HTTP Method

Use a method-specific helper to configure a path for every operation that uses that HTTP method.

`WithGet("path")` applies to Get, Get All, and Get Page because they all use `GET`. The `WithPost`, `WithPut`, `WithPatch`, and `WithDelete` helpers apply in the same way to their HTTP methods.

Add uses `POST` when no identifier is provided and `PUT` when an identifier is provided. Update uses `PUT` for a full update and `PATCH` for a partial update.

When a Set also has a general `WithEndpoint` configuration, add the method-specific configurations after it.

### A Path for One Operation

Several operations can use the same HTTP method. To configure only one of them, name its operation descriptor type in the configuration function:

```csharp
.WithGet((GetPageOperationDescriptor _) =>
    "courses/{courseId}/students")
```

An operation descriptor describes the operation being executed. Here, `GetPageOperationDescriptor` means that this path is used only for Get Page.

The returned value replaces Flux.REST's normal path composition. It must include the Set path and any operation identifier needed by the API. If the value is a relative path, the Service's `HttpClient` resolves it against its base address.

When a Set also has a general `WithEndpoint` configuration, add the operation-specific configuration after it.

## Operation Parameters

Operation parameters provide values for path placeholders and query parameters.

### Named Parameters

Use name-and-value pairs when a path contains named placeholders:

```csharp
var parameters = new OperationParameterCollection(
    new[]
    {
        new KeyValuePair<string, object>("courseId", 42),
        new KeyValuePair<string, object>("status", "active")
    });

var studentsPage = await studentSetContext.GetPageAsync(
    offset: 0,
    limit: 20,
    parameters: parameters);
```

For the path configured earlier:

```text
courses/{courseId}/students
```

the `courseId` parameter produces:

```text
courses/42/students
```

Parameter names must match the placeholders exactly, including uppercase and lowercase letters. When named parameters are supplied, they must provide a value for every placeholder in the path.

### Automatic Query Values

A named parameter that is not used by a path placeholder is added to the query string. Get Page also adds its non-null `offset` and `limit` values.

In the named-parameter example above, `courseId` fills the path placeholder, while `status` is not used in the path. Flux.REST therefore produces:

```text
courses/42/students?status=active&offset=0&limit=20
```

If the configured path already contains a query string, Flux.REST keeps it and adds the automatic values after it.

The path configuration helpers accept a `queryComplete` argument. Set it to `true` when the configured query is already complete. Flux.REST still replaces named placeholders, but it does not add unused named parameters or pagination values.

### Positional Parameters

You can also provide parameter values without names:

```csharp
var parameters = new OperationParameterCollection(
    new object[] { 42, 7 });
```

Positional values replace placeholders from left to right, regardless of the placeholder names. For example:

```text
courses/{courseId}/students/{studentId}
```

becomes:

```text
courses/42/students/7
```

The number of positional values must exactly match the number of placeholders. Positional values that are not used in the path are not added to the query string.

Named parameters are usually easier to read and can also provide optional query values. Use positional parameters when replacement order is sufficient.

## Configure a Complete HTTP Request

For full control over an outgoing request, return an `HttpRequestMessage` from the endpoint configuration:

```csharp
.WithEndpoint((GetOperationDescriptor operation) =>
{
    var request = new HttpRequestMessage(
        HttpMethod.Get,
        $"courses/{operation.Id}");

    request.Headers.Add("X-Client-Version", "2");
    return request;
})
```

The returned message is the request that Flux.REST sends. You can set its URI, HTTP method, headers, and content directly.

Flux.REST still runs request interceptors, sends the request through the Service's `HttpClient`, and processes the response. For related configuration, continue to [HTTP Client Configuration](03.http-client.md), [JSON Serialization Configuration](04.json-serialization.md), and [Request Interception](05.request-interception.md).
